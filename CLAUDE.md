# DOSTYQ TAXI — описание проекта для Claude

## Кто работает с тобой
Владелец проекта — не программист. Он работает на **Windows** в VS Code, телефон для проверки — Android.
- Объясняй простыми словами по-русски, короткими шагами.
- **Flutter и Android Studio на компьютере НЕ установлены, и владелец не хочет их ставить.** Приложение собирается в облаке: код хранится в приватном репозитории GitHub, APK собирает **GitHub Actions** после каждого push. Владелец скачивает APK из раздела Actions/Releases и ставит на телефон.
- Ты пишешь код, делаешь commit и push, следишь за сборкой (`gh run list`, `gh run view --log-failed`) и сам исправляешь ошибки сборки. Перед push внимательно проверяй код, потому что каждая сборка занимает 5–10 минут и тратит бесплатные минуты GitHub.
- Если владелец позже установит Flutter, можно перейти на `flutter run` с телефона по USB.
- После каждого шага говори, что проверить на телефоне, и жди ответа.
- Не делай всё сразу: один этап → проверка на телефоне → следующий.
- Если нужна ручная настройка (Firebase, Google Play), пиши инструкцию по шагам: куда нажать и что ввести.
- Никогда не клади ключи и пароли в чат и в публичные файлы.

## Что за проект
Бренд — **ALAKOL TAXI** (константа `kBrand` в `lib/config.dart`; папка, репозиторий и id приложения `kz.dostyq.taxi` остались прежними). Районы — Достык, Ушарал и другие — показываются под брендом своими названиями.

Такси и доставка для посёлка **Достык** (Алакольский район, Казахстан), около 8 000 жителей, затем Ушарал и соседние посёлки.
- Цены: по посёлку **500 ₸**, до Таможни/КПП и обратно **1 500 ₸**, другая поездка длиннее 3 км **2 000 ₸**, место до Ушарала (160 км) **3 500 ₸**, вся машина до Ушарала **14 000 ₸** (4 места × 3 500), доставка по посёлку **400 ₸**. Цены меняются в админке.
- Водители платят сервису **фиксированную подписку** (ориентир 4 000 ₸ в неделю или 15 000 ₸ в месяц) через Kaspi на счёт ИП, на старте **3 месяца бесплатно**. Плата за каждый заказ (30/100 ₸) — только как настройка на будущее. Клиент платит водителю напрямую наличными или переводом Kaspi, через сервис эти деньги не проходят.
- Подписка заканчивается → напоминания за 3 дня, за 1 день и в день окончания (push + плашка у водителя); после окончания заказы не приходят, пока не продлит.
- Водитель подключается с документами: права (2 стороны), техпаспорт (2 стороны), фото машины; тип машины — легковая или грузовая. ИП и уведомление E-license в анкете **не требуются** (решение владельца 31.10.2026; юридическую сторону владелец уточняет сам). Админ проверяет и одобряет анкету.
- Грузовое — как в inDrive: клиент может указать свою цену, грузовые водители предлагают цены, клиент выбирает.
- При регистрации клиента и водителя — галочка согласия на обработку персональных данных и оферта.
- Полное ТЗ: `reference/TZ-DOSTYQ-TAXI.pdf`. Прочитай его перед началом работы.

## Технологии
- **Flutter** (одно приложение, два режима: «Клиент» и «Водитель»; Android в первую очередь).
- **Firebase**: Firestore (заказы в реальном времени), Authentication, Cloud Messaging (push), Cloud Functions (назначение водителя, коды входа).
- Карта: **flutter_map** + OpenStreetMap, позже 3D (MapLibre).
- Админка: **Flutter Web** в той же папке (отдельная точка входа) или отдельная веб-страница — на этапе 4.
- Вход: на время разработки — Firebase Phone Auth с тестовыми номерами. Для запуска — код в **WhatsApp** через провайдера WhatsApp Business API + запасной звонок-сброс (через Cloud Function и custom token).
- Важно: по закону Казахстана персональные данные нужно хранить на серверах в Казахстане. Firebase — только для разработки и теста; перед открытым запуском нужен переезд. Не завязывай логику жёстко на Firebase: доступ к данным — через отдельный слой (repository).

## Данные (Firestore, черновик)
- `users/{uid}`: name, phone, role (`client`/`driver`/`manager`/`admin`), homePlace, rating.
- `drivers/{uid}`: car, plate, color, status (`offline`/`online`/`busy`/`blocked`), location {lat,lng,updatedAt}, subscriptionUntil, balance, rating, skips.
- `orders/{id}`: clientId, from {label,lat,lng}, to {label,lat,lng}, service (`local`/`border`/`delivery`), price, payment (`cash`/`kaspi`), comment, status (`searching`/`offered`/`accepted`/`arrived`/`riding`/`done`/`cancelled`), offeredTo, driverId, createdAt, createdBy (`app`/`manager`).
- `trips/{id}` (рейсы в Ушарал): driverId, date, time, direction, seats [4], bookings, parcels.
- `places/{id}`: name, synonyms[], category, lat, lng. `streets/{id}`: name, nameKz, synonyms[], houses.
- `settings/main`: цены, таймеры (20 с на ответ водителя, 3 мин до показа всем, 5 мин ожидания), пороги рейтинга.

## Логика заказа
1. Клиент создаёт заказ → статус `searching`.
2. Сервер (Cloud Function) предлагает его ближайшему свободному водителю на линии → `offered`, 20 секунд.
3. Нет ответа или «Пропустить» → следующему по близости. Через 3 минуты — всем и менеджеру.
4. Принял → `accepted`, клиент видит машину на карте и время подачи (координаты водителя каждые 3–5 с).
5. «Я на месте» (кнопка активна ближе 100 м) → `arrived`, «Поехали» → `riding`, «Завершить» → `done`, оценка 1–5.

## Этапы (делай по порядку)
1. **GitHub и облачная сборка**: приватный репозиторий, GitHub Actions собирает APK, владелец ставит на телефон пустое приложение.
2. **Основа**: экраны клиента и водителя без сервера (данные в памяти), переключатель режима, стиль как в прототипе.
3. **Firebase**: вход, заказы в реальном времени: клиент заказал → водитель видит → принял → клиент видит статус.
4. **Карта**: карта Достыка, точка подачи, маршрут, машина движется, поиск адресов с опечатками и ориентирами, «Указать на карте».
5. **Админка и менеджер**: окно заявок менеджера, водители, подписки/напоминания, ориентиры и улицы, тарифы.
6. **Межгород и доставка**: рейсы в Ушарал с выбором мест, посылки, доставка.
7. **Подготовка к запуску**: push-уведомления, иконка и название, сборка APK, публикация в Google Play, вход через WhatsApp.
