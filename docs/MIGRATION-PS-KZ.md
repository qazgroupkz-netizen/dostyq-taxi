# Переезд с Firebase на свой сервер в Казахстане (ps.kz)

Зачем: по закону РК персональные данные (телефоны, имена, документы водителей) должны храниться на серверах в Казахстане. Firebase — только для разработки и теста.

## Что арендуем
- **VPS на ps.kz** (тариф уровня Basic-3: 2–4 ядра, 4–8 ГБ памяти, SSD). SSH-ключ уже создан: `C:\Users\user\.ssh\dostyq_ed25519` (закрытый ключ никому не отправлять).
- Домен, например `alakoltaxi.kz`, и бесплатный HTTPS-сертификат (Let's Encrypt).

## Что ставим на сервер
| Сейчас (Firebase) | Будет на сервере |
|---|---|
| Firestore (заказы, водители, рейсы, тарифы, улицы) | **Supabase** (PostgreSQL + Realtime) в Docker |
| Firebase Auth (вход по SMS) | Supabase Auth + свой код входа: **SMS через казахстанского провайдера**, позже WhatsApp |
| Нет (нужен Blaze) | Отправка push: сервер → FCM (Android, бесплатно) и Web Push (iPhone) |
| GitHub Pages (сайт) | Тот же сайт на своём сервере (nginx) |
| Тайлы OpenStreetMap, Nominatim, OSRM (общие сервера) | Пока общие; при росте — свои (тайлы и маршруты Казахстана) |

## Что меняется в коде
Доступ к данным уже вынесен в отдельный слой — меняются только эти файлы, экраны остаются прежними:
- `lib/data/orders.dart` — `FirestoreOrderRepository` → `SupabaseOrderRepository`
- `lib/data/catalog.dart` — районы, тарифы, места, улицы
- `lib/data/drivers.dart` — анкеты и документы водителей (документы — в хранилище файлов Supabase)
- `lib/data/trips.dart` — межгород

Вход пока напрямую вызывает Firebase в нескольких местах — перед переездом соберём его в один файл `lib/data/auth.dart`:
- `lib/main.dart`, `lib/admin/admin_main.dart` — кто вошёл
- `lib/screens/auth_screen.dart` — код из SMS, сохранение имени
- `lib/state.dart`, `client_screen.dart`, `trip_screen.dart`, `driver_trips_screen.dart`, `driver_apply_screen.dart` — номер телефона и выход

Правила доступа Firestore превращаются в правила строк PostgreSQL (RLS): клиент видит свои заказы, водитель — заказы своего района, админ — всё.

## Порядок
1. Купить VPS и домен, прислать IP-адрес (пароли в чат не присылать — вход по SSH-ключу).
2. Поставить Supabase, nginx, HTTPS, резервные копии базы каждую ночь.
3. Собрать вход в `lib/data/auth.dart` (на Firebase, без изменения поведения) — проверить на телефоне.
4. Написать Supabase-версии репозиториев, переключать по одной настройке в `lib/config.dart`.
5. Подключить SMS-провайдера (договор от ИП), код входа через свой сервер.
6. Перенести тестовые данные (тарифы, места, улицы, районы); реальные данные водителей — только на новый сервер.
7. Push-уведомления с сервера.
8. Перед открытым запуском: `kTestMode = false`, убрать тестовые номера, отключить проект Firebase (или оставить только FCM для push на Android).
